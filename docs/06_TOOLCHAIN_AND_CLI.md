# Aerix (arx) — Toolchain & CLI Architecture

> **CLI Executable:** `arx` (`arx.py` / `arx.bat`)  
> **Philosophy:** *Frictionless developer workflow — from single-command script execution to release-grade binary builds.*

---

## 1. CLI Commands & Overview

The `arx` CLI provides a unified interface for compilation, testing, and execution:

```text
USAGE:
    arx <COMMAND> [OPTIONS] <FILE>

COMMANDS:
    run        Compile and immediately execute an Aerix program in memory
    build      Compile an Aerix file down to an optimized native binary (.exe)
    emit-c     Generate and output the intermediate C99 source file
    check      Perform lexical, syntax, and semantic type checking without compiling
    new        Scaffold a new Aerix project with main.arx and aerix.toml
    doctor     Diagnose system toolchains (C compiler, paths, architecture)
    test       Execute automated unit and integration tests
    version    Print Aerix compiler and toolchain version
    help       Print command-line help information
```

---

## 2. Command Details & Usage Examples

### 2.1 `arx run` (Development Mode)
Compiles the `.arx` source into a temporary native binary and executes it immediately:
```bash
arx run main.arx
```
*Behind the scenes:* Transpiles to a temporary `.c` file in `.aerix_cache/`, calls `gcc -O2`, runs the resulting executable, and cleans up.

### 2.2 `arx build` (Production Release Mode)
Generates a standalone, fully optimized native executable:
```bash
# Basic build
arx build main.arx -o app.exe

# Maximum release optimization
arx build main.arx --release -o app.exe
```

**Release Flags Passed to GCC:**
```text
-O3                # Maximum optimization & vectorization
-march=native      # Target host CPU instruction set
-flto              # Whole-program Link Time Optimization
-s                 # Strip debug symbols for minimal binary size
-DNDEBUG           # Disable runtime assertion overhead
```

### 2.3 `arx emit-c` (Code Inspection Mode)
Outputs the human-readable C99 code generated by the compiler. Crucial for verifying that Aerix abstractions incur zero runtime cost:
```bash
arx emit-c main.arx -o output.c
```

### 2.4 `arx check` (Fast Type-Check)
Quickly analyzes the code for syntax or type errors in milliseconds without invoking GCC:
```bash
arx check main.arx
```

## 3. Windows Integration (`arx.bat`)

To allow developers to simply type `arx` in PowerShell or Command Prompt, a batch launcher is placed in the project root:

```bat
@echo off
python "%~dp0arx.py" %*
```

---

## 4. Multi-File Project Configuration (`aerix.toml`)

For larger projects, Aerix supports an optional `aerix.toml` manifest:

```toml
[package]
name = "my_game"
version = "0.1.0"
authors = ["Developer <dev@example.com>"]
entry = "src/main.arx"

[build]
opt_level = 3
target_c = "c99"
output_dir = "bin/"
flags = ["-flto", "-march=native"]

[dependencies]
# Native C libraries to link
link = ["raylib", "opengl32", "gdi32", "winmm"]
```
